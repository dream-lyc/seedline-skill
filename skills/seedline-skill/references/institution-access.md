## 建议的最小服务端调整（待确认）

目标是复用现有签名协议、内容结构和领域查询，只增加机构获准的只读能力，不重建题库或扩展为通用动态权限系统。

1. 提供机构专用凭据授权入口。建议由有效 `org_admin` 为本人创建／吊销绑定本机构的只读凭据；普通机构成员不因有账号就自动获得导出权限。凭据仍使用现有存储及生命周期机制，最大 scope 集合为 `contracts:read/content:read/media:read`。入口路径与响应结构须在正式接口设计中确认，本 skill 不预定不存在的路径。
2. 机器身份区分平台管理员与机构只读主体；每次请求校验当前用户、角色、机构状态／有效期和凭据状态。`/me` 返回可核验的机构 ID、roles、有效 scopes 和环境；不允许客户端传入 organization_id 来切换主体。
3. 对机构主体，内容列表和详情在服务端按当前机构获准的题库范围过滤。默认只能读取 published 的雅思题包／试卷与托福试卷、available 的托福题组。已知 ID、分页、搜索、依赖详情都使用相同授权。究竟哪些已发布内容对该机构开放应沿用实际授权业务，不能在 skill 中假定全库可读。
4. 媒体读取复用媒体领域，但只允许该机构可读题目所引用的素材和参考答案媒体；不能借 media:read 任意下载学生录音或范围外文件。签名 URL 生成前执行同样授权。
5. 机构凭据不能提交内容、上传媒体、查看管理员提交记录、管理平台凭据或批准录题连接。现有管理员导入能力保留原边界。

若后续需要机构教师独立获取、指定机构可读内容配置或独立解析视频全集，应根据明确需求扩展；不在本次 skill 设计中预建复杂成员授权表、订阅套餐、批量导出任务或通用权限框架。

## Spec 确认范围

仓库 `AGENTS.md` 要求：“未经确认不得创建或修改任何 Spec 文件。”实施前需要向用户明确确认下列有限变更：

- 当前“机器凭据签发与读取仅限非机构 admin”，拟增加“有效机构管理员可获本人／本机构只读凭据”的例外；不开放平台凭据管理及录入写权限。
- 当前“content:read 还须当前管理员权限”，拟增加机构可读范围内的题目／试卷／依赖与关联媒体读取。
- 机构角色不会自动获得题库管理；增加的仅是明确授予的只读开放接口能力，保留现有平台后台、发布及导入授权边界。

影响涉及身份鉴权、机构授权入口、me 契约、内容与媒体资源过滤，以及上述相关 Spec。用户只要求设计 skill 并不视为已确认这些 Spec 修改。本文件记录建议，不替代批准。

## 开通后的最小验收

| 场景 | 可观察结果 |
| --- | --- |
| 有效机构凭据获取雅思完整大题 | 保留全部材料、小题、答案与解析；与同版本录入对象 Schema 一致 |
| 获取雅思单科卷／明确四科范围 | 单科展开全部题包；四科分别保留真实单科结构，无虚构整卷对象 |
| 获取托福完整试卷 | 八模块、全部候选分支和依赖题组齐全；共享引用只获取一次 |
| 凭据无对应 scope、机构暂停／到期或角色撤销 | 服务端拒绝后续请求，skill 报告正确原因且不扩大权限 |
| 请求草稿、下架或范围外题目／媒体 | 列表和详情均无越权数据；已知 ID 也不能绕过 |
| 机构凭据请求上传、发布或管理员连接 | 被服务端拒绝；skill 没有发起这些调用 |
| 依赖缺失、下载失败、契约不兼容 | 保存已有进度并标为部分完成／待校验，不能宣布整卷完整 |
| 结果交接给录入流程 | 领域格式一致；原 ID 保留为来源事实，不把导出文件直接重发造成重复录入 |

本版已核对接口与字段来源；尚未执行真实机构凭据联调，也未提供独立只读取题客户端。部署和接口契约验收后应更新本节及 SKILL.md 的接入状态。
